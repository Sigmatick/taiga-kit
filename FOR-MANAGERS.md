# Taiga в Claude Code — для менеджеров

Вести задачи обычными фразами в чате: смотреть бэклог, заводить карточки, двигать по доске,
раскладывать техническое задание в эпики и истории.

Терминал нужен **один раз** — запустить установщик. Дальше нет.

## Установка

> **Ставится один раз на компьютер, а не на каждый проект.** Поставили —
> архив больше не нужен. Следующий проект подключается фразой в чате:
> «подключи эту папку к проекту `<слаг>`». Переустанавливать не надо.


Распаковать архив и запустить:

| Система | Что сделать |
|---|---|
| macOS | двойной щелчок по `setup-macos.command` |
| Windows | двойной щелчок по `setup-windows.cmd` |
| Linux | в терминале: `bash setup-linux.sh` |

Установщик задаст несколько вопросов.

**Кто вы** — ответить `1` (менеджер).

**Адрес Taiga** — то, что в адресной строке браузера до первого слэша,
например `https://taiga-ticket.example.kz`.

**Логин и пароль** — ваши от Taiga. **Пароль при вводе не отображается**: ни звёздочек,
ни курсора. Это нормально, печатайте вслепую и нажмите Enter.

**Слаг проекта** — установщик покажет список, выбрать нужный из левого столбца.
Проектов можно подключить сколько угодно: после каждого спросит, нужен ли ещё.
Закончить — пустая строка.

**Папка проекта** — куда класть настройку. Если папки с кодом нет, подойдёт любая,
например `~/Documents/DomCom`; установщик создаст её сам.

**Ежедневный отчёт** — ответить `y`, если нужен.

В конце установщик покажет задачи подключённого проекта. Показал — всё работает.

### Если система не даёт запустить

**macOS:** «не удаётся открыть, разработчик не установлен» — правая кнопка по файлу →
«Открыть» → в окне ещё раз «Открыть».

**Windows:** запускайте `setup-windows.cmd`, а не `.ps1` — он обходит политику
выполнения сам и не закрывает окно. Если окно всё равно мгновенно закрылось,
откройте PowerShell в папке с файлами и выполните две строки — тогда ошибка
останется на экране:

```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup-windows.ps1
```

## Как работать

Откройте Claude Code **с папкой проекта** и пишите словами.

| Что нужно | Что написать |
|---|---|
| Посмотреть задачи | что в бэклоге |
| Только свои | покажи мои задачи |
| Одну карточку подробно | покажи 144 |
| Завести задачу | создай историю: не работает экспорт отчёта |
| Завести с описанием | создай историю «нужен сервер» с описанием: 2 vCPU, 4 ГБ, Ubuntu |
| Карточки встреч на неделю | заведи карточки встреч на эту неделю |
| Двинуть по доске | переведи 144 в Ready for test |
| Назначить | назначь 144 на Фабера |
| Комментарий | напиши в 144, что тестирование отложено |
| Приложить файл | приложи ТЗ.docx к карточке 177 |
| Посмотреть вложения | что приложено к карточке 127 |
| Забрать файлы | скачай вложения карточки 127 |
| Забрать всё по проекту | выгрузи все вложения проекта |
| **Разобрать документ** | разложи ТЗ.docx на эпики и истории |
| Создать проект | создай проект на базе DomCom |
| Кто в проекте | кто участвует в проекте design-and-smm |
| Добавить человека | добавь Юлию Порох в проект design-and-smm |
| Отчёт | собери отчёт за вчера |
| **План против факта за день** | собери сводку план-факт |
| **То же за неделю** | собери план-факт за неделю |
| Список проектов | покажи список проектов |

**Папка решает, с каким проектом вы работаете.** Открыли сессию в папке DomCom — работаете
с DomCom. Нужен другой проект, не переключаясь, — так и скажите: «покажи бэклог egsv».

## Подключить ещё проект

Терминал не нужен. Открыть Claude Code с папкой нового проекта и написать:

```
подключи эту папку к проекту domcom
```

**Слаг — одно слово сразу после `/project/`,** до следующей косой черты. Всё, что
дальше, — это страница, на которую вы зашли, а не часть слага:

| Адрес | Слаг |
|---|---|
| `…/project/domcom/kanban` | `domcom` |
| `…/project/egsv/us/159` | `egsv` |
| `…/project/digital-police/task/294?kanban-status=12` | `digital-police` |
| `…/project/projectmanager/backlog` | `projectmanager` |

Дефис входит в слаг целиком: `digital-police`, `argus-control`.

**Слаг не равен названию.** `argus-control` в интерфейсе называется «Engineering
department»: проект переименовали, а адрес остался. Не знаете слаг — спросите
«покажи список проектов».

## Что происходит при записи

Перед любым изменением вам покажут, что именно будет сделано, и спросят согласия.
Ничего не запишется, пока вы не ответите «да».

Это не формальность. Пример из реальной проверки: документ был помечен как тестовый,
а карточки собирались в рабочий проект — система заметила противоречие и остановилась
спросить, вместо того чтобы засорить бэклог команды.

## Самое полезное: разбор технического задания

Присланный заказчиком документ превращается в структурированный бэклог за один заход.

Положите файл в папку проекта и напишите: «разложи ТЗ.docx на эпики и истории».

Дальше по шагам: прочитает документ, предложит разбивку, **спросит про непонятные места**,
покажет план целиком и дождётся вашего «да». Только потом заведёт карточки.

Повторный запуск того же плана ничего не продублирует: создаётся только недостающее.

## Ежедневный отчёт

Кто что создал, взял в работу и закрыл за предыдущий рабочий день — по всем проектам сразу.
Складывается отдельным файлом на день, будни в 09:00, если согласились при установке.

В отчёте: сводка «человек × проект», поимённый список переходов по доскам, список созданного
и раздел про то, что из нового нельзя взять в работу из-за плохого оформления.

**«Закрыл» означает, кто именно переставил карточку**, а не на ком она числилась: цифры
берутся из журнала переходов.

Попросить вручную: «собери отчёт за вчера».

## Вечерняя сводка «план против факта»

Будни в 19:00, файлом `.md` в Telegram. Берёт вашу карточку «Чек-статус»
за этот день, вынимает из неё план и сверяет с тем, что за день реально
сдвинулось в трекере. **Только ваши проекты** — те, что записаны за вами
в карте команды. CTO видит все.

Устроен по проектам, а не по людям. На каждый проект:

| | Всего | Было в плане |
|---|---:|---:|
| Закрыто | 5 | 4 |
| Ушло на проверку | 7 | 5 |
| Вернули в баги | 0 | 0 |
| Взято в работу | 3 | 2 |

Колонка **«было в плане»** отвечает на единственный вопрос дня: делали ли то,
о чём договорились утром. Без неё отчёт показывает активность, но не дисциплину.

Ниже по каждому проекту — таблица переходов (время, что произошло, номер,
название, кто, был ли в плане) и блок **«было в плане, но не двигалось»**.
В начале файла — сводная таблица по всем вашим проектам.

Считаются четыре события: закрыто, ушло на проверку, вернули в баги, взято
в работу. Перекладывание внутри бэклога работой не считается и в отчёт
не попадает.

### В пятницу — ещё и за неделю

Тем же запуском в 19:00 приходит второй файл: понедельник–пятница.
Формат тот же, но карточка в нём — одной строкой, по последнему событию
недели: иначе за неделю набегают сотни строк. Счётчики при этом считают
все переходы, поэтому «закрыто 5» при четырёх строках «закрыто» — не ошибка,
а карточка, которую закрыли и потом снова тронули. В файле это оговорено.

Если неделя ещё не кончилась, окно обрывается на сегодня — отчёт не делает
вид, будто знает про будущие дни.

Условие одно: **задачи в плане записаны ссылками** на карточки. Проза
не сверяется — отчёт честно покажет такой день как «без ссылок, сверить
не с чем». Подробности и образец — в регламенте `РЕГЛАМЕНТ-Taiga.md`.

## Два режима уведомлений

В боте (`проекты?`) есть переключатель:

| | |
|---|---|
| 🧪 **сразу** | карточка приходит, как только попала на проверку — для тестировщиков |
| 🌙 **вечером** | вечерний файл «план против факта» — для руководителей |

Руководителю нужен второй. Мгновенные 🧪 по всем проектам — это десятки
сообщений в день: 15 и 16 октября на проверку ушло 38 и 35 карточек.

Карточки, назначенные лично на вас, приходят сразу в обоих режимах —
это отдельный механизм, переключателем он не управляется.

## Уведомления в Telegram

Бот `@MegacamPulseControl_bot`. Что приходит:

| Когда | Что |
|---|---|
| будни 08:30 | напоминание провести дейлик и что на вас назначено |
| будни 19:00 | файл «план против факта» по вашим проектам |
| пятница 19:00 | дополнительно файл за неделю, понедельник–пятница |
| сразу | «вам назначена карточка» — когда карточка попала на вас в BUG или ToDo |

Больше ничего не приходит. Промежуточные сводки убраны намеренно: руководителю
нужен итог дня, а не поток событий.

Значки: 🐞 баг · 📋 ToDo · ▶ в работе · 🧪 на тесте · ⏳ зависло ≥7 дней · ✅ закрыто.

**Чтобы подключиться:** найдите бота, нажмите Start и скажите администратору.
Бот не имеет права писать первым — пока он вам не ответит, рассылки не будет.
Ваш Start и есть согласие её получать.

Уже назначенные карточки в уведомления не попадут: при подключении ставится
отсечка, иначе первым делом прилетело бы два десятка сообщений.

## Настройка бота кнопками

Напишите боту `проекты?` — придёт список с галочками:

```
✅ 🧪 сразу: ДА        ⬜ 🌙 вечером: нет
⬜ Adminstration       ⬜ Argus
⬜ BuroPropuskov       ⬜ CheckPoint
…
⬜ Все проекты         🔄 Обновить список
Отписаться             Готово
```

| Кнопка | Что делает |
|---|---|
| 🧪 **сразу** | карточка приходит в момент поступления — для тестировщиков |
| 🌙 **вечером** | только в вечерней сводке — для руководителей |
| проект | следить за ним; «Все проекты» отмечает разом |
| 🔄 **Обновить список** | подтянуть проекты, если завели новый |
| Отписаться | перестать получать совсем |

Режим и проекты независимы: включили режим — проекты всё равно надо отметить,
иначе присылать нечего, и бот об этом прямо напишет.

Отметили «Все проекты» — новые проекты будут подхватываться сами, каждый день.
Выбрали вручную — новый не навяжут.

Меняется в любой момент, переустанавливать ничего не нужно. То же самое
текстом: `проекты все`, `проекты domcom, checkpoint`, `проекты`, `сразу`,
`вечером`, `стоп`.

## Недельный план и дейлики

Если в «Планировании недели» поставить ссылку на **историю**, а в дейликах
называть **задачи внутри неё**, вечерняя сводка свяжет одно с другим:

```
| Цель                          | Задач | Закрыто | В работе | Не начато | В дейликах |
| EGSV #2 · Обращения от НПО    |     7 |       3 |        2 |         2 |          4 |
```

И отдельно покажет задачи, закрытые за неделю, которых **в дейликах
не называли**, — работа шла мимо плана.

Ссылка на задачу вместо истории тоже подойдёт: возьмётся её родитель.

## Операционка

Заведите на проект карточку «Техническое сопровождение — ДД.ММ.ГГГГ».
Инженеры пишут в **комментарии**, что к ним прилетело и как решили:

```
заявка на доступ к СКО от Бюро — выдал до 24.10
упал NTP в Туркестане — перезапустил, следить
```

Почему в комментарии, а не в описание: у комментария есть автор и время,
описание перезаписывается без следа — пятый пишущий затрёт первых четверых.

Вечером эти записи попадут в сводку отдельным разделом, с разбивкой
по людям. Это единственное место, где видно работу, на которую карточек
не заводят.

## Карточки встреч заводятся сами

Понедельник, 08:00: на каждого руководителя создаются планирование недели,
пять чек-статусов и ретроспектива. Руками заводить не нужно, переименовывать
нельзя — по названию их находит вечерняя сводка.

Нужна другая неделя или другой состав — скажите в чате: «заведи карточки
встреч на следующую неделю», «убери из списка руководителей Чечушкова».

## Чего система не делает намеренно

**Не удаляет задачи.** В Taiga удаление необратимо, отката нет. Удалять — руками
в интерфейсе, осознанно.

**Не добавляет людей в проект по своей инициативе.** Успешный ответ означает, что человеку
уже ушло письмо, — это действие за пределами трекера. Только по прямой просьбе.

**Не просит пароль и токен в переписке.** Всё написанное в чат остаётся в записи разговора.
Вход выполняется только установщиком, вами.

## Если что-то пошло не так

**«Всё перестало приходить после отпуска».** Вход в Taiga живёт 8 дней и
продлевается сам, пока вы работаете. Компьютер простоял дольше — напишите
«обнови токен», не поможет — запустите установщик, он предложит войти.
За трое суток до конца система предупредит сама.

**«Список пустой, хотя задачи есть».** Скорее всего истёк вход. Напишите «обнови токен».
Не помогло — запустите установщик заново, он предложит войти.

Это важно понимать: Taiga на запрос без авторизации отвечает не отказом, а **пустым
списком**. То есть «задач нет» и «я не вошёл» выглядят одинаково. Поэтому пустой ответ —
повод проверить вход, а не решить, что бэклог пуст.

**«Не понимает, какой проект».** Напишите «проверь настройку» — покажет, какой проект
подхватился. Скорее всего сессия открыта не с той папкой.

**«Создалась не та сущность».** В Taiga четыре разных рода: эпик, история, задача внутри
истории, вопрос. Фраза «создай задачу» неоднозначна — говорите точнее: «создай историю»
или «создай задачу внутри 144».

## Что стоит знать про доску

**Колонка и «закрытость» — разные вещи.** Закрывающих колонок в проекте обычно несколько
(`Done`, `Archived`, `Cancelled`), и система смотрит на признак закрытости, а не на название.
Поэтому «покажи открытые» вернёт правильный список, даже если колонки переименуют.

**Задача не существует сама по себе** — только внутри истории. Если нужен отдельный пункт,
это история, а не задача.

**Одинаковые названия не создаются дважды.** Попытка завести карточку с существующим
названием остановится и покажет номер уже имеющейся.
