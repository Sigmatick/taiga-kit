# Taiga в Claude Code — для менеджеров

Это инструкция для тех, кто ведёт задачи, а не пишет код. Терминал понадобится
один раз при установке; дальше всё делается обычными фразами в чате.

## Коротко: восемь шагов

Если нужна только последовательность действий — вот она. Подробности по каждому пункту ниже.

### Установка — один раз

**1.** Открыть Терминал: Cmd+Пробел → «Терминал»

**2.** Поставить плагин, две команды подряд:

```
claude plugin marketplace add Sigmatick/taiga-kit
```

```
claude plugin install taiga-kit@taiga-kit
```

**3.** Поставить программу и войти в Taiga:

```
git clone https://github.com/Sigmatick/taiga-kit.git ~/taiga-kit && cd ~/taiga-kit && ./install.sh
```

Спросит адрес, логин и пароль. Пароль при вводе не отображается — печатайте вслепую, Enter.

**4.** В конце покажет список проектов. Показал — установка закончена.

### Подключить проект — на каждый свой

**5.** Узнать слаг: открыть проект в браузере и посмотреть адрес.

```
https://<инстанс>/project/domcom/kanban
                          ^^^^^^ это слаг
```

**6.** Создать папку под проект и подключить:

```
mkdir -p ~/Documents/DomCom && cd ~/Documents/DomCom && taiga init domcom
```

Папка нужна только чтобы Claude понимал, с каким проектом вы работаете. Код в ней не обязателен.

**7.** Проверить:

```
taiga ls --open
```

Показал задачи — проект подключён.

### Пользоваться

**8.** Открыть Claude Code **с папкой этого проекта** и писать словами:

| Что нужно | Что написать |
|---|---|
| Увидеть задачи | `что в бэклоге` |
| Свои | `покажи мои задачи` |
| Одну подробно | `покажи 144` |
| Завести | `создай историю: не работает экспорт` |
| Двинуть по доске | `переведи 144 в Ready for test` |
| Назначить | `назначь 144 на Фабера` |
| Комментарий | `напиши в 144, что тест отложен` |
| Разобрать ТЗ | `разложи ТЗ.docx на эпики и истории` |
| Создать проект | `создай проект на базе DomCom` |

Перед любой записью покажут, что будет сделано, и спросят согласия.

### Если сломалось

| Симптом | Команда |
|---|---|
| Список пустой, хотя задачи есть | `taiga refresh`, не помогло — `taiga login` |
| Непонятно, какой проект подхватился | `taiga status` |

## Что это даёт

Вместо того чтобы открывать Taiga в браузере, искать проект, кликать по карточкам —
вы пишете в чат словами:

> покажи открытые задачи
> создай историю: не работает экспорт отчёта
> переведи 42 в In progress
> назначь 42 на Полынкова
> разложи вот этот документ на эпики и истории

Последнее — самое полезное. Присланное заказчиком техническое задание превращается
в структурированный бэклог за один заход: с эпиками, историями и вопросами по тем
местам, где документ недоговаривает.

## Установка — один раз

Понадобится Терминал. Если застрянете на любом шаге — покажите этот файл разработчику,
ему это пять минут.

**1. Открыть Терминал.** Cmd+Пробел, набрать «Терминал», Enter.

**2. Поставить плагин** — скопировать и выполнить по очереди:

```
claude plugin marketplace add Sigmatick/taiga-kit
```

```
claude plugin install taiga-kit@taiga-kit
```

**3. Поставить программу и войти в Taiga:**

```
git clone https://github.com/Sigmatick/taiga-kit.git ~/taiga-kit && cd ~/taiga-kit && ./install.sh
```

Спросит адрес Taiga, ваш логин и пароль. **Пароль при вводе не отображается** — ни звёздочек,
ни курсора. Это нормально, печатайте вслепую и нажмите Enter.

В конце покажет список проектов — значит всё получилось.

## Подключить проект — по разу на каждый

Подключение означает: сказать программе, что вот эта папка на компьютере относится
вот к этому проекту в Taiga.

**1. Узнать слаг проекта.** Слаг — это то, что стоит в адресе браузера:

```
https://taiga-ticket.../project/domcom/kanban
                               ^^^^^^
```

Не название из интерфейса: проект могли переименовать, а адрес остался прежним.

**2. Перейти в папку проекта и подключить:**

```
cd ~/путь/к/папке/проекта
taiga init domcom
```

Создастся один маленький файл с настройкой. Код проекта не затрагивается.

**Нет папки с кодом?** Заведите любую — например `~/Documents/DomCom-задачи` — и подключите её.
Работать с задачами можно из любой папки, код для этого не нужен.

## Как работать

Откройте сессию Claude Code **с папкой этого проекта** и пишите словами.

| Что нужно | Что написать |
|---|---|
| Посмотреть задачи | «что в бэклоге» |
| Только свои | «покажи мои задачи» |
| Одну карточку подробно | «покажи 144» |
| Завести задачу | «создай историю: текст задачи» |
| Двинуть по доске | «переведи 144 в Ready for test» |
| Назначить | «назначь 144 на Фабера» |
| Комментарий | «напиши в 144, что тестирование отложено» |
| Разобрать документ | «разложи ТЗ.docx на эпики и истории» |

**Папка решает, с каким проектом вы работаете.** Открыли сессию в папке DomCom — работаете
с DomCom. Нужен другой проект, не переключаясь, — так и скажите: «покажи бэклог egsv».

## Что происходит при записи

Перед любым изменением вам покажут, что именно будет сделано, и спросят согласия.
Ничего не запишется, пока вы не ответите «да».

Это не формальность. Пример из реальной проверки: документ был помечен как тестовый,
а карточки собирались в рабочий проект — система заметила противоречие и остановилась
спросить, вместо того чтобы засорить бэклог команды.

## Чего система не делает намеренно

**Не удаляет задачи.** В Taiga удаление необратимо, отката нет. Удалять — руками
в интерфейсе, осознанно.

**Не добавляет людей в проект.** Успешный ответ означает, что человеку уже ушло письмо, —
это действие за пределами трекера.

**Не просит пароль и токен в переписке.** Всё написанное в чат остаётся в записи разговора.
Вход выполняется только в Терминале, вами.

## Если что-то пошло не так

**«Список пустой, хотя задачи есть».** Скорее всего истёк вход. Выполните в Терминале:

```
taiga refresh
```

Не помогло:

```
taiga login
```

Это важно понимать: Taiga на запрос без авторизации отвечает не отказом, а **пустым
списком**. То есть «задач нет» и «я не вошёл» выглядят одинаково. Поэтому пустой ответ —
повод проверить вход, а не решить, что бэклог пуст.

**«Не понимает, какой проект».** Проверьте, что сессия открыта в правильной папке:

```
taiga status
```

Покажет, какой проект подхватился.

**«Создалась не та сущность».** В Taiga четыре разных рода: эпик, история, задача внутри
истории, вопрос. Фраза «создай задачу» неоднозначна — говорите точнее: «создай историю»
или «создай задачу внутри 144».

## Что стоит знать про доску

**Колонка и «закрытость» — разные вещи.** Закрывающих колонок в проекте обычно несколько
(`Done`, `Archived`, `Cancelled`), и система смотрит на признак закрытости, а не на название.
Поэтому «покажи открытые» вернёт правильный список, даже если колонки переименуют.

**Задача не существует сама по себе** — только внутри истории. Если нужен отдельный пункт,
это история, а не задача.

**Одинаковые названия не создаются дважды.** Попытка завести карточку с существующим
названием остановится и покажет номер уже имеющейся.
