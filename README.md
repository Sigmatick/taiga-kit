# taiga-kit

Свой инструмент для работы с трекером Taiga. Один код, два входа: плагин Claude Code
и обычный CLI для терминала, скриптов и cron.

От сторонних плагинов не зависит.

> **Ведёте задачи, а не пишете код?** [ДЛЯ-МЕНЕДЖЕРОВ.md](ДЛЯ-МЕНЕДЖЕРОВ.md) — без терминальных подробностей.
> **Разработчику** — [ДЛЯ-РАЗРАБОТЧИКОВ.md](ДЛЯ-РАЗРАБОТЧИКОВ.md): дозорный, реестр, разбор тикетов по коду.

## Что внутри

| | |
|---|---|
| `bin/taiga` | CLI: чтение, создание, статусы, исполнители, комментарии, применение плана |
| `skills/taiga` | навык Claude Code: когда и как звать CLI, ловушки Taiga |
| `skills/spec-to-backlog` | навык: разбор документа в эпики и истории через план-файл |
| `install.sh` | установка CLI для работы вне Claude Code |

## Установка

**Для Claude Code** — из вашего репозитория:

```
/plugin marketplace add <владелец>/<репозиторий>
/plugin install taiga-kit@<маркетплейс>
```

Локально, без публикации:

```bash
claude --plugin-dir ~/Development/taiga-kit
```

**Для терминала и скриптов:**

```bash
./install.sh
```

Спросит адрес инстанса, логин и пароль; пароль не отображается и в историю команд
не попадает. Затем покажет список проектов.

## Как это устроено и как распространять

**Плагин** — эта папка. **Маркетплейс** — список плагинов, файл
`.claude-plugin/marketplace.json` (он тут же). **Источник** — путь на диске или репозиторий
GitHub.

Установка всегда две команды: подключить маркетплейс, поставить из него плагин. Различается
только адрес источника.

### Установка в один заход

Скрипты спрашивают всё нужное и делают плагин, программу, вход и подключение проекта.

| Система | Что запустить |
|---|---|
| macOS | двойной щелчок по `setup-macos.command` |
| Windows | правая кнопка по `setup-windows.ps1` → «Выполнить с помощью PowerShell» |

Если Windows откажет из-за политики выполнения, открыть PowerShell и выполнить:

```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup-windows.ps1
```

**Windows-скрипт не проверялся на живой машине.** Написан под PowerShell 5.1 (который идёт
с системой) и 7, файл сохранён с BOM, вывод переключён в UTF-8 — но прогона не было.
Нужен Python с отмеченной галочкой «Add Python to PATH» при установке.
На Windows права `600` на файлах с токеном не действуют: там нет такой модели доступа.

Ниже — то же самое вручную, по шагам.

### Способ 1. Локально, со своей машины

```bash
claude plugin marketplace add ~/Development/taiga-kit
claude plugin install taiga-kit@taiga-kit
```

Правки в папке подхватываются сразу. GitHub не нужен. Работает только на этой машине.

### Способ 2. Копией папки

Скопировать папку коллеге (архив, облако, сеть). У него:

```bash
claude plugin marketplace add /путь/куда/скопировал/taiga-kit
claude plugin install taiga-kit@taiga-kit
```

Обновления придётся копировать заново.

### Способ 3. GitHub

Один раз у автора:

```bash
gh repo create taiga-kit --private --source=. --push
```

Дальше у любого в команде:

```bash
claude plugin marketplace add <владелец>/taiga-kit
claude plugin install taiga-kit@taiga-kit
```

Обновление — `claude plugin marketplace update taiga-kit`.

### Проверить, что встало

```bash
claude plugin list          # taiga-kit должен быть enabled
claude plugin details taiga-kit
```

## Установка с нуля: полный путь

Шесть шагов. Первые два — в Claude Code, остальные в терминале.

**1. Поставить плагин** — любым способом выше.

**2. Проверить, что навыки видны.** В сессии Claude Code спросить «что в бэклоге» — должен
загрузиться навык `taiga-kit:taiga`. Если вместо него грузится другой плагин трекера,
отключить конкурента: `claude plugin disable <имя>`.

**3. Поставить CLI для терминала** (нужен и самому плагину, и для скриптов с cron):

```bash
cd <папка плагина> && ./install.sh
```

Если каталог `~/.local/bin` не в PATH, установщик предложит дописать строку в `~/.zshrc`.

**4. Войти в Taiga.** Установщик спросит сам, либо отдельно:

```bash
taiga login
```

Спросит адрес инстанса, логин и пароль. **Пароль вводит человек**, он не отображается
и не попадает в историю команд. Долгоживущих токенов в Taiga нет: токен — результат логина.

**5. Подключить проект.** Перейти в папку проекта:

```bash
taiga projects          # посмотреть слаги
taiga init <слаг>       # создать .claude/tracker.local.md
```

**6. Проверить:**

```bash
taiga status            # кто я, какой проект подхватился
taiga ls --open         # список задач
```

Пункты 5 и 6 повторяются для каждого проекта. Пункты 1–4 — один раз на машину.

### Что где лежит после установки

| | |
|---|---|
| `~/.local/bin/taiga` | CLI |
| `~/.taiga.{url,token,refresh}` | токен, права 600 |
| `<проект>/.claude/tracker.local.md` | привязка папки к проекту трекера, без секретов |
| плагин | в кэше Claude Code, обновляется из маркетплейса |

## Подключение проекта

Из папки проекта:

```bash
taiga init <слаг>
```

Слаг — то, что в адресе: `https://<инстанс>/project/<слаг>/`. **Не название:** проект могли
переименовать, а адрес остался. Список — `taiga projects`.

Создаётся `.claude/tracker.local.md` с адресом инстанса и путём к токену. **Секрета в нём
нет**, файл можно коммитить.

## Токен

Долгоживущих личных токенов в Taiga нет: токен — результат логина, и он срочный.

```bash
taiga refresh    # продлить без пароля
taiga login      # если истёк и refresh
```

Раскладка на выбор:

| | Где | Когда |
|---|---|---|
| общая | `~/.taiga.{url,token,refresh}`, права 600 | одна учётная запись на всё |
| на проект | `<проект>/.taiga/`, каталог 700 | у проекта своя учётная запись |

Для второй: `taiga init <слаг> --here` и `taiga login --here`. Строка `.taiga/` дописывается
в `.gitignore` **до** записи секрета — иначе между записью и правкой игнора остаётся окно,
в которое попадёт `git add -A`, а из истории git секрет не отзывается.

Токен наследует права своей учётной записи целиком: ограничение даёт служебная запись
с урезанной ролью, а не раскладка файлов.

## Команды

```
taiga status | projects
taiga init <слаг> [--here]
taiga login [--here] | refresh

taiga ls [--open] [--mine] [--status X] [--kind us|task|issue|epic]
taiga show <номер>

taiga new "текст" [--kind task --parent N] [--assign имя] [--status X]
taiga mv <номер> "<статус>"
taiga assign <номер> <имя>
taiga comment <номер> "текст"

taiga plan  <файл.json>    показать, что будет создано
taiga apply <файл.json>    создать недостающее

taiga sync [--dry] [--ref N]   подтянуть статус истории по её задачам (только вперёд)
taiga triage [--days N] [--all] [--comment]
                          проверить оформление нового: что нельзя взять в работу

taiga watch [--dry] [--days N] [--install|--uninstall]
                          дозорный: заготовки триажа в папках проектов
taiga registry [--scan] [--forget <слаг>]
                          реестр «слаг → папка с кодом», ~/.taiga-kit/projects.json
taiga users [-p <слаг>]    люди инстанса или участники проекта и его роли
taiga new-project "Имя" --desc "описание"
       [--duplicate <слаг>]   копия устройства проекта: каталоги, роли, поля
       [--sample <слаг>]      только колонки канбана
       [--users "А,Б" --role "Back"]   добавить участников (уйдут письма)
       [--public] [--init]
```

`-p <слаг>` и `-y` ставятся после подкоманды. Без `-y` любая запись показывает превью
и спрашивает согласия.

## План-файл

```json
{
  "project": "egsv",
  "epics": [
    { "subject": "Эпик",
      "stories": [
        { "subject": "История", "description": "…", "assign": "Фамилия",
          "status": "Backlog", "tasks": [ { "subject": "Шаг" } ] }
      ] }
  ],
  "stories": []
}
```

`taiga apply` идемпотентен: существующее по названию пропускается, создаётся только
недостающее, ничего не переписывается. Повторный прогон безопасен.

## Ловушки Taiga, заложенные в поведение

Проверены вызовами на живом инстансе, а не вычитаны из документации.

**Пустой список не означает «ничего нет».** На запрос без авторизации Taiga отвечает `200`
и пустым списком, а не отказом: «бэклог пуст» и «я не авторизован» неразличимы. Поэтому
первым вызовом всегда проверяется личность — `GET /users/me`, анонимно отвечает `401`.

**Род единицы — адрес ресурса, а не поле.** Эпик, история, задача и вопрос живут на разных
ресурсах. Задача не существует сама по себе, только внутри истории.

**Идентификаторы статусов пер-проектные.** Значение из другого проекта переводит не туда или
даёт отказ по правам. Статусы не кэшируются и задаются названием.

**Закрытость — по признаку `is_closed`, а не по названию колонки.** Закрывающих статусов
в проекте бывает несколько.

**Признак закрытости на объекте устаревает.** Taiga дублирует `is_closed` на саму карточку
и **не пересчитывает его**, когда меняют каталог статусов или возвращают карточку в работу.
Проверено: 5,5% объектов инстанса расходятся — карточка в `Done` с `is_closed: false` на
объекте, и наоборот. **Закрытость определяется по каталогу статусов проекта, а не по полю
объекта.** Поле объекта — устаревающая копия, каталог — источник правды.

**Выключенный модуль не мешает создать объект:** создание в отключённом разделе может
вернуть успех, хотя раздела нет.

**Ключа идемпотентности нет** — повтор создаёт второй объект. Перед созданием идёт поиск
по названию.

**Добавление участника: поле `username` принимает логин и почту, и ведут они себя по-разному.**
По логину Taiga требует, чтобы человек был «контактом» — то есть уже делил с вами проект;
иначе `400` `The user must be a valid contact`. По почте эта проверка не срабатывает.
Проверено: себя в чужой проект по логину добавить нельзя, по почте — можно.
Поля `user` и `email` не принимаются вовсе: `400` `username: This field is required`.

Осложняется тем, что **`GET /users` почту не отдаёт** — только `id` и `username`. Почта есть
в `GET /memberships?project=<id>`, поэтому её приходится собирать обходом видимых проектов.

**Пустой исполнитель принимается с кодом `200`** и молча оставляет карточку ничьей.
У приглашённых по почте участников идентификатор пользователя пустой, поэтому при разрешении
имени они отбрасываются.

**Правка — цикл с версией.** Устаревшая версия и отсутствующая версия дают разные отказы:
первый повторяем после перечитывания, второй бессмыслен.

## Чего инструмент не делает намеренно

- Не удаляет единицы работы: в Taiga это необратимо.
- Не добавляет участников: успешный ответ означает отправленное человеку письмо.
- Не создаёт спринты.
- Не добавляет участников по своей инициативе: успешный ответ означает отправленное
  письмо. Только по явной просьбе, ключом `--users`, с отдельным подтверждением.
- Не просит токен в переписке.
