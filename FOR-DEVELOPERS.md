# Taiga в Claude Code — для разработчиков

Всё, что умеет роль «менеджер», плюс дозорный и разбор тикетов по коду.
Если нужно только вести задачи — [FOR-MANAGERS.md](FOR-MANAGERS.md).

Терминал нужен **один раз** — запустить установщик. Дальше всё фразами в чате.

## Установка

> **Windows:** десктопное приложение Claude не прописывает себя в PATH.
> Если установщик скажет «claude не найден» — поставьте командную строку:
> `npm i -g @anthropic-ai/claude-code`, затем запустите установщик снова.
> Всё остальное он поставит и без неё.

> **Ставится один раз на компьютер, а не на каждый проект.** Поставили —
> архив больше не нужен. Следующий проект подключается фразой в чате:
> «подключи эту папку к проекту `<слаг>`». Переустанавливать не надо.


Запустить `setup-macos.command` (macOS), `setup-windows.cmd` (Windows)
или `bash setup-linux.sh` (Linux) и на вопрос о роли ответить **`2` — разработчик**.

Он поставит плагин и программу, выполнит вход, подключит первый проект, наполнит реестр
и предложит поставить ежедневный отчёт и дозорного.

## Что появляется на машине

| | |
|---|---|
| программа и плагин | ставятся один раз |
| токен | один на человека, права `600` |
| `<проект>/.claude/tracker.local.md` | какому проекту Taiga соответствует папка |
| реестр «слаг → папка с кодом» | нужен дозорному: он видит тикет и должен знать, куда класть разбор |
| `<проект>/.claude/триаж/` | заготовки разбора |
| два фоновых задания | отчёт и дозорный |

Токен один на человека, привязка — на каждую папку.

## Как работать

Открыть Claude Code с папкой проекта и писать словами.

| Что нужно | Что написать |
|---|---|
| Посмотреть задачи | что в бэклоге · покажи мои задачи |
| Карточку подробно | покажи 412 |
| Завести, двинуть, назначить | создай историю: … · переведи 412 в Done · назначь 412 на Фабера |
| **Что ждёт разбора** | что по триажу |
| **Разобрать тикет** | разбери 412 |
| Подтянуть статусы историй по задачам | синхронизируй статусы |
| Проверить оформление нового | что из нового плохо оформлено |
| Отчёт | собери отчёт за вчера |
| Подключить эту папку | подключи эту папку к проекту checkpoint |
| Сменить период опроса | проверяй трекер каждые два часа с 8 до 20 |
| Брать только свои задачи | бери в триаж только мои задачи |
| Брать только баги и ToDo | бери в триаж только BUG, Bug (reopen) и ToDo |

## Дозорный

Раз в час с 9 до 19 по будням проверяет трекер и кладёт заготовку разбора в папку проекта:
`<проект>/.claude/триаж/<номер>-<заголовок>.md`.

В заготовке — текст тикета, ссылка, исполнитель, замечания по оформлению и пустые разделы
про код. **Их заполняет разведка — сама, без просьбы:** через полчаса после дозорного,
каждый час с 9:35 до 19:35 по будням.

**Существующие файлы не перезаписываются.** Заготовка создаётся один раз; ваши правки и
изменённый статус остаются. Закрытые тикеты заготовок не получают.

**Предохранитель на 20 заготовок за раз.** При первом запуске и после массового импорта их
набирается полсотни; тогда останов без записи и без сдвига отметки времени.

Период меняется фразой: «проверяй трекер каждые два часа с 8 до 20» или «проверяй и по
выходным». Выключить: «сними дозорного с расписания».

## Где об этом разговаривать

Не в общем чате, а **в сессии Claude Code, открытой с папкой проекта**. Заготовки лежат
в этой же папке, поэтому там они видны сразу:

| Что спросить | Что получите |
|---|---|
| что по триажу | список: что уже разобрано, что ещё ждёт |
| покажи разведку по 444 | готовый разбор, без повторного поиска |
| разбери 412 | разбор того, что ещё не разобрано |

**Разобранное второй раз не разбирается.** У заготовки есть статус: `разведка готова`
значит, что разбор уже лежит в файле — его перескажут, а не станут искать заново.
Повторный поиск по репозиторию — это второй счёт за ту же работу.

Нужно глубже — так и скажите: «по 444 копни глубже, посмотри ещё Keychain».

## Автоматическая разведка

Раз в час разведка берёт заготовки, которые ещё никто не смотрел, и заполняет разделы
про код: где искать, что предположительно происходит, что делать дальше.

| | |
|---|---|
| сколько за раз | 3 |
| сколько в сутки | 10 |
| очередь | сначала назначенные на человека, потом ничьи; свежие вперёд |
| что берёт | только то, что дозорный положил: BUG, Bug (reopen), ToDo |

Пределы стоят не из скупости: каждый разбор тратит токены учётной записи.

**Разведка читает код и ничего больше.** Ей выданы только чтение, поиск и обход файлов —
ни записи, ни git, ни команд. В репозитории чужая работа в процессе, и потерять её нельзя.

### Её ответу нельзя верить на слово — и это проверяется

Каждая ссылка вида `файл:строка` ищется в репозитории. Не нашлась — в заготовке появится:

```
> ⚠ не найдено в репозитории: Services/AuthStore.swift:88. Ссылкам из списка верить нельзя.
```

Отдельно ищутся слова «подтвердил», «воспроизвёл», «причина в». Разведка кода не запускала
и права на такие утверждения не имеет; если напишет — вы это увидите предупреждением.

### Второй раз не разбирается

У заготовки есть статус. `разведка готова` значит, что разбор уже в файле: в сессии проекта
его перескажут, а не станут искать заново. Нужно глубже — скажите прямо:
«по 444 копни глубже, посмотри ещё Keychain».

## Разбор тикета руками

Если ждать очереди некогда — «разбери 412» в сессии с папкой проекта. Разбор ищет место в коде, ссылается на
`файл:строка`, строит гипотезу и предлагает следующий шаг.

**Он читает код, но не собирает приложение и не воспроизводит баг.** Поэтому в выводе
«предположительно» и «судя по коду», а не «подтвердил». Если бы там стояло «причина в»,
вы бы доверяли разбору больше, чем он стоит.

Не нашлось — так и пишет, где искал и почему не нашёл. Выдуманная ссылка на файл хуже
честного «не нашёл»: по ней пойдут и потеряют время.

Тикет непонятен — ставит статус «нужен вопрос» и пишет, что именно неясно. Это и есть
польза триажа.

### Чего разбор не делает

- **не правит код** — это отдельная ваша просьба
- **не пишет в трекер** — заготовка лежит локально, это правильное место для черновых гипотез
- **не трогает рабочее дерево** — ни `git stash`, ни смена ветки

Последнее важно: в репозитории могут быть сотни несохранённых файлов, и это чужая работа
в процессе.

### Пример из боевой проверки

Тикет EGSV #157 «Отключать PTZ-джойстик при переключении на камеру без PTZ».

Разбор нашёл в `CameraTerminalViewModel.swift:276` строку, которая это и делает, рядом
комментарий с описанием ровно той же ситуации, тест на это поведение и коммит
«fix: пульт ПТЗ закрывается сам на камере без ПТЗ — сборка 11».

Вывод: тикет, похоже, уже закрыт кодом, висит в `Ready for test` — скорее всего его просто
не перепроверили после сборки 11. С пометкой «не проверено запуском».

## Уведомления в Telegram

Бот `@MegacamPulseControl_bot`. Что приходит:

| Когда | Что |
|---|---|
| будни 08:30 | что на вас открыто, что зависло в работе ≥7 дней |
| будни 18:30 | что закрыли за день, что осталось в работе |
| сразу | «вам назначена карточка» — когда карточка попала на вас в BUG, Bug (reopen) или ToDo, со ссылкой |
| сразу | 🔎 «разведка по коду» — когда разобран тикет, назначенный на вас |
| сразу | 🧪 «в Ready for test» — тестировщикам, когда карточка пришла на проверку |

**Тестировщикам.** Напишите боту `проекты все` или перечислите слаги —
`проекты domcom, checkpoint`. Буду присылать карточки, пришедшие на проверку,
только по вашим проектам. `проекты` — посмотреть текущие, `стоп` — отписаться.
Меняется в любой момент, переустанавливать ничего не надо.

Значки в сообщениях: 🐞 баг · 📋 ToDo · ▶ в работе · 🧪 на тесте · ⏳ зависло ≥7 дней ·
✅ закрыто · 🔎 разведка готова.

**Чтобы подключиться:** найдите бота, нажмите Start и скажите администратору —
он свяжет ваш чат с учётной записью Taiga. Бот не может написать первым: пока
вы сами ему не напишете, он не имеет права вам отвечать. Ваш Start и есть
согласие получать рассылку.

Уже назначенные карточки в уведомления не попадут: при подключении ставится
отсечка, иначе первым делом прилетело бы два десятка сообщений по тому,
что и так давно на вас висит.

## Настройка бота кнопками

Напишите боту `проекты?` — придёт список с галочками:

```
✅ 🧪 сразу: ДА        ⬜ 🌙 вечером: нет
⬜ Adminstration       ⬜ Argus
⬜ BuroPropuskov       ⬜ CheckPoint
…
⬜ Все проекты         🔄 Обновить список
Отписаться             Готово
```

| Кнопка | Что делает |
|---|---|
| 🧪 **сразу** | карточка приходит в момент поступления — для тестировщиков |
| 🌙 **вечером** | только в вечерней сводке — для руководителей |
| проект | следить за ним; «Все проекты» отмечает разом |
| 🔄 **Обновить список** | подтянуть проекты, если завели новый |
| Отписаться | перестать получать совсем |

Режим и проекты независимы: включили режим — проекты всё равно надо отметить,
иначе присылать нечего, и бот об этом прямо напишет.

Отметили «Все проекты» — новые проекты будут подхватываться сами, каждый день.
Выбрали вручную — новый не навяжут.

Меняется в любой момент, переустанавливать ничего не нужно. То же самое
текстом: `проекты все`, `проекты domcom, checkpoint`, `проекты`, `сразу`,
`вечером`, `стоп`.

## Подключить ещё проект

Открыть Claude Code с папкой и написать: «подключи эту папку к проекту `<слаг>`».

Слаг — то, что в адресе браузера между `/project/` и следующим слэшем. Не название:
проект могли переименовать, а адрес остался. Не знаете — «покажи список проектов».

Реестр обновится сам, дозорный подхватит проект со следующей проверки.

## Ежедневный отчёт

Кто что создал, взял и закрыл за предыдущий рабочий день — по всем проектам. Будни в 09:00.
В конце раздел триажа: что из нового нельзя взять в работу.

Цифры берутся из журнала переходов, поэтому «закрыл» означает, кто именно переставил
карточку, а не на ком она числилась.

## Коммитить ли `.claude/триаж/`

Решайте сами. За: разбор полезен команде, не надо делать дважды. Против: гипотезы устаревают,
а история репозитория засоряется черновиками.

Не коммитить — добавьте `.claude/триаж/` в `.gitignore` проекта.

Конфиг `.claude/tracker.local.md` коммитить стоит: секретов в нём нет, а коллегам он
сэкономит шаг подключения.
