# Taiga в Claude Code — для разработчиков

Всё, что умеет роль «менеджер», плюс дозорный и разбор тикетов по коду.
Если вам нужно только вести задачи — читайте [ДЛЯ-МЕНЕДЖЕРОВ.md](ДЛЯ-МЕНЕДЖЕРОВ.md).

## Установка

Запустить установщик и выбрать роль **2 — разработчик**:

```
./setup-macos.command        # macOS
.\setup-windows.ps1          # Windows
```

Он поставит плагин и программу, выполнит вход, подключит первый проект, наполнит реестр
и предложит поставить дозорного.

Вручную то же самое:

```
claude plugin marketplace add Sigmatick/taiga-kit
claude plugin install taiga-kit@taiga-kit
git clone https://github.com/Sigmatick/taiga-kit.git ~/taiga-kit && cd ~/taiga-kit && ./install.sh
cd <папка проекта> && taiga init <слаг>
taiga registry --scan
taiga watch --install
```

## Что где лежит

| | |
|---|---|
| `~/.local/bin/taiga` | программа |
| `~/.taiga.{url,token,refresh}` | токен, права 600 |
| `<проект>/.claude/tracker.local.md` | какой проект Taiga соответствует папке |
| `~/.taiga-kit/projects.json` | реестр «слаг → папка с кодом» |
| `~/.taiga-kit/watch-state.json` | когда дозорный проверял в последний раз |
| `<проект>/.claude/триаж/` | заготовки разбора |

Токен один на человека, привязка — на каждую папку.

## Реестр

Связь «папка → проект» лежит в папке. Обратной — «слаг → где код» — в Taiga нет, а она нужна
дозорному: он видит новый тикет в `egsv` и должен знать, куда класть заготовку.

```
taiga registry                    что в реестре
taiga registry --scan             найти подключённые проекты и внести
taiga registry --forget <слаг>    убрать
```

Заполняется сам при `taiga init`. `--scan` нужен один раз, для проектов, подключённых раньше.
Исчезнувшие папки помечаются при выводе и не отдаются как рабочие пути.

## Дозорный

Раз в час с 9:05 до 19:05 по будням проверяет трекер и кладёт заготовку разбора в папку
проекта: `<проект>/.claude/триаж/<номер>-<заголовок>.md`.

```
taiga watch                  одна проверка
taiga watch --dry            показать, ничего не записывая
taiga watch --days 3         при первом запуске — за сколько суток смотреть назад
taiga watch --install        поставить расписание
taiga watch --install --every 2 --start 8 --end 20
                             свой период: каждые 2 часа с 8 до 20
taiga watch --install --all-days     включая выходные
taiga watch --uninstall      снять
```

В заготовке — текст тикета, ссылка, исполнитель, замечания по оформлению и **пустые** разделы
про код. Их заполняет разбор, отдельно и по просьбе: он стоит токенов, а нужен не по каждому
тикету.

**Существующие файлы не перезаписываются.** Заготовка создаётся один раз; ваши правки и
изменённый статус остаются. Закрытые тикеты заготовок не получают.

**Предохранитель на 20 заготовок за раз** (`--max`). При первом запуске и после массового
импорта их набирается полсотни; тогда останов без записи и без сдвига отметки времени.

## Разбор тикета

В сессии Claude Code с папкой проекта:

```
что по триажу        список: номер, заголовок, статус
разбери 412          заполнить разделы про код
```

Разбор ищет место в коде, ссылается на `файл:строка`, строит гипотезу и предлагает следующий
шаг. Статус в файле меняется на `разведка готова`.

**Он читает код, но не собирает приложение и не воспроизводит баг.** Поэтому в выводе
«предположительно» и «судя по коду», а не «подтвердил». Если бы там стояло «причина в»,
вы бы доверяли разбору больше, чем он стоит.

Не нашлось — так и пишет, где искал и почему не нашёл. Выдуманная ссылка на файл хуже
честного «не нашёл»: по ней пойдут и потеряют время.

### Чего разбор не делает

- не правит код — это отдельная ваша просьба
- не пишет в трекер — заготовка лежит локально, это правильное место для черновых гипотез
- не трогает рабочее дерево — ни `git stash`, ни смена ветки

Последнее важно: в репозитории могут быть сотни несохранённых файлов, и это чужая работа
в процессе.

## Прочие команды

```
taiga sync [--dry]           подтянуть статус истории по её задачам (только вперёд)
taiga triage [--all]         проверить оформление нового
taiga plan|apply <файл>      разложить план в бэклог, идемпотентно
taiga new-project …          создать проект, в том числе дубликатом
taiga users [-p <слаг>]      люди инстанса или участники проекта
```

Полный список и устройство — [README.md](README.md).

## Коммитить ли `.claude/триаж/`

Решайте сами. За: разбор полезен команде, не надо делать дважды. Против: гипотезы устаревают,
а история репозитория засоряется черновиками.

Если не коммитить — добавьте в `.gitignore` проекта:

```
.claude/триаж/
```

Конфиг `.claude/tracker.local.md` коммитить стоит: секретов в нём нет, а коллегам он сэкономит
шаг подключения.
